## Overview

This is the closing step of the release loop: monitor the release, handle fallout, and capture anything learned for next time.

## Post-Release Tasks

- [ ] Announce release (Discord, forums, etc.) — see [Phase 70](70-publishing-releases.md#announcement-tips) if not done already
- [ ] Update any pinned issues
- [ ] Monitor for critical bug reports
- [ ] Prepare hotfix if needed
- [ ] Update the guides with any lessons learned

⚠️ **If updating guides requires renumbering or inserting a new phase file:** use 10-, 20-, 30-, 40-, ... instead of 1-, 2-, 3-, 4-, ... A future phase can then slot in as e.g. `21-` without renumbering every file after it (and every cross-reference to those filenames) the way inserting a new phase would under 1-2-3-4 numbering. This convention doesn't need retrofitting onto the current guides — apply it the next time a renumber is needed.
